# 0.1.1 AI 修复记录

## 已确认的问题

- 0.1.0 使用固定 120 秒的 `AbortSignal.timeout`；请求完成后计时器仍会触发，原生 HTTP JS 包装器也未清理相关监听器，可能重复操作已经关闭的网络资源。超时处理原本只覆盖等待响应头，没有正确分类正文读取中断。
- 文档处理任务只在系统角色中描述，用户消息仅包含 PDF 文本。某些模型或网关弱化系统消息时，可能把截断的论文片段理解为需要继续对话的输入。用户报告的询问 / 续写文本原本会被直接记为成功。
- API Key 原本有意只保存在会话内存中，重启后丢失；任务继续时采用创建时的服务和模型，界面没有明确说明新设置不影响旧任务。

用户附件中的 `.NET / EasyPipes / iGameCenter / GetFanRPM` 堆栈来自风扇控制软件，不是 Paperead 的 Rust / WebView2 调用栈，因此不能用该弹窗定位 Paperead 的翻译错误。未使用用户真实密钥或原始论文复现外部服务调用。

## 修复与使用

- 使用可清除的单片段计时器，覆盖请求和正文，原生网络取消、流结束和资源释放分别处理。默认 300 秒，可调 30–900 秒。
- 四种协议支持 SSE 流式输出，处理跨网络包的 UTF-8 / SSE 边界，检测截断和意外中断；兼容非流式 JSON，可关闭流式参数。
- 默认两个片段并行，可调 1–3；片段默认 3000 字符，可调 1000–6000，输出 Token 上限可调。进度显示等待时间和字数，阅读页显示流式草稿。只有完整通过的片段才持久保存。
- 系统与用户消息均明确翻译 / 重排任务、源文档边界，以及禁止提问、摘要、补写和虚构内容。检测到明显的对话 / 续写建议时停止该任务并保留错误，不能保证所有模型输出的语义准确度。
- Windows 系统凭据存储保存 API Key，并按服务地址隔离；重启自动使用，支持替换和清除。取消勾选安全保存后回到会话模式；设置状态也会保留。密钥不进入 IndexedDB、备份、日志或安装包。
- 任务卡展示实际模型 / 地址。切换配置后可选择「继续原任务」或「使用当前配置重新处理」。重新处理生成新版本，保留旧结果与批注。

关闭旧版后安装 0.1.1，再到偏好设置填写 API Key 并保存一次。旧版没有保存过密钥，升级不能自动恢复旧会话密钥。默认沿用同一应用标识、资料库名称和结构。

## 验证

- 28 项单元测试：原有数据完整性，加上已完成请求不再触发旧计时器、响应头 / 正文超时、取消、四种 SSE 协议、UTF-8 拆包、流断开、截断、错误脱敏、指令约束、拒绝跑题、并行检查点、重复点击、模型切换、凭据恢复 / 替换 / 删除 / 会话模式。
- 8 项真实 Edge 界面流程通过，包括 PDF、批注、Markdown、导出、备份、AI 处理和 429 恢复。首次 PDF 测试等待资源准备，串行恢复测试显式选择并行数 1。
- `scripts/smoke-ai-windows.mjs` 使用独立原生程序和 WebView2 资料目录、本机模拟服务与临时假密钥验证：流式输出和实时预览、完全退出后恢复系统密钥、切换地址 / 模型 / 密钥后重新处理、拒绝报告中的跑题文本、原生流取消、真实 30 秒正文超时、超时后切回前一服务并成功连接。共 10 次原生请求，JavaScript 错误 0。测试结束清除两条测试凭据，不读取用户密钥。
- macOS / iOS 密钥链仍未真机验证；Android 尚未接入持久安全存储。真实模型质量、服务商限流 / 代理兼容性仍需对应 API 和文献验证。

最终 0.1.1 Release 另通过 `scripts/smoke-windows.mjs` 的真实 PDF 导入 / Worker / 翻页 / 批注、Markdown 持久化和 3 次原生 JSON 接口请求检查，JavaScript 错误 0。最终安装包为 17,558,691 字节，校验值见 [Windows 构建说明](WINDOWS-BUILD.md)。本次使用临时程序副本进行原生测试，没有覆盖用户已安装的 0.1.0 或读取其资料。
