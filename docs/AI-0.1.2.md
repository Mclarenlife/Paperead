# 0.1.2 全文翻译与重排

## 问题与改动

- 旧逻辑先按物理页分割请求，阅读器又按当前页过滤结果；很多短页面也会单独等待模型。现在先恢复段落，再跨页合并为正文批次，默认每批最多 6000 字符，并受输出 Token 预算约束。20 页短文本回归样例的请求数从 20 降为 2；这是请求数比较，不代表真实服务的固定加速比例。
- 翻译和重排始终是一份连续 Markdown。请求边界只用于处理、检查点和续传；阅读、批注、Markdown / HTML / TXT / DOCX 导出使用整份结果，不自动插入页标题、分页注释或分隔线。原始 PDF 仍保留翻页阅读。
- 原文对照模式逐段生成 `> 原文`、空行、译文。原文由程序从提取文本插入，模型只返回带段落标记的译文，减少输出 Token。程序校验标记数量和顺序，缺段、重复、乱序不会记为完成；导出会移除控制标记。关闭对照只输出译文。
- 提示词同时约束任务、来源文本、整篇文档结构和相邻只读上下文，禁止擅自续写、提问、总结和重复输出上下文。重排保留原文语言。
- 全应用共用请求队列，最多同时 3 个请求，同一服务地址遵循配置中的并行数（默认 2）。排队可取消，超时从实际请求开始计时。相同文献同类任务不能同时运行；任务固定自己的配置和本次运行密钥，不受中途切换设置影响。
- 一批失败后停止领取新批次，已经发出的其他请求允许返回并保存；不会因为并行请求报错而丢弃成功结果。继续任务只补齐未完成批次。用户主动暂停仍中止正在进行的请求。
- 并行结果按来源位置保存。阅读预览只展示已连续完成的前文和紧接着的一批草稿，后续提前完成的内容等待前文。已完成正文的 Markdown 渲染被记忆，避免每次流式增量都重新解析整篇文档。
- 新批注使用全文文字偏移，并绑定具体结果版本，全文完成后可划词批注。工作台的「查看结果」打开对应历史版本；旧结果的页内批注通过兼容容器保留。
- PDF 提取利用文本行的坐标、间距、缩进和字号保留段落。旧版导入的 PDF 首次创建新任务时重新提取并缓存，无需重新导入；原始 PDF、文件哈希和原文高亮坐标不变。无文字页面会明确提示 OCR，其余可提取的正文仍能处理。

## 使用

关闭旧版，安装 0.1.2。在「AI 阅读助手」中勾选「原文对照（逐段引用原文）」，再开始翻译。也可以在偏好设置中默认启用。已经创建的任务保留原来模式；需要新模式时使用「使用当前配置重新处理」，旧结果和批注仍保留。

「导出 → MD」输出一份完整文件。未完成任务导出已有正文时，会在缺失位置标记未完成批次，避免误认为完整结果。批次大小、并行数、单批超时和输出上限在偏好设置的「请求与性能设置」调整；减小批次有助于慢模型或较小上下文窗口，增加批次可减少网络往返。

- 9 项 Edge 界面流程已通过，包含实际 PDF 的旧版提取升级、两页一次请求、每段原文引用、完整 Markdown 下载、重排全文、历史版本选择、全文批注重载与定位；同时回归原始 PDF、笔记、备份、其他格式导出及移动宽度。
- Windows 0.1.2 Release 的 9 项原生检查已通过，共 9 次本机模拟请求、JavaScript 错误 0：SSE、凭据重启恢复、服务/模型切换、对照及全文批注重启恢复、拒绝跑题、取消、真实 30 秒正文超时、超时后再次连接、实际两页 PDF 的四段提取与单请求处理。测试使用隔离的 WebView2 资料目录和临时密钥，不读取用户文献或密钥，不覆盖已安装应用。报告保存于 `.tmp/windows-ai-012-report.json`。
- TypeScript、Vite、Rust Release 与 NSIS 构建通过；程序的 Windows 文件版本为 0.1.2。安装包为 17,561,689 字节，SHA-256 见 [Windows 构建说明](WINDOWS-BUILD.md)。

未使用用户真实 API 验证模型语义质量或速度。段落恢复基于 PDF 文本和几何信息，复杂多栏、公式、表格及扫描图像仍需人工核对或专业版面/OCR 解析。超长段落会按句子或文字边界拆成对照单元，以避免单次响应超限；任务支持批次级续传，不把中断中的不完整译文当作完成。并行模型的术语一致性依赖模型能力及来源上下文，不能保证完全一致。
