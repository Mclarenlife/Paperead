# 0.1.3 文献管理与数据保护

本次只实现功能审查清单中用户批准的第 1–6 项，保留 0.1.2 的连续全文 Markdown、逐段原文对照和 AI 请求机制。

## 1. 文献库快捷管理

卡片和列表右上角的「更多操作」提供元数据编辑、移动文献集、修改标签、阅读状态和移入回收站。阅读器继续使用同一个文献信息编辑组件。无需先打开 PDF 才能删除文献。

## 2. 批量整理和导出

勾选文献后显示操作栏，可全选当前搜索结果、移动文献集、添加 / 移除 / 替换标签、修改阅读状态、批量删除和导出。切换搜索或筛选后清除选择，动作只作用于当前选择的活动记录。移动、标签和状态修改在事务中提交。

批量 ZIP 包含所选原始 PDF 与文献信息 JSON；示例记录只有原创演示导读，按 Markdown 导出。它与设置中的「完整资料库备份」用途不同：后者包含笔记、批注、AI 结果和回收站。

## 3. 回收站、恢复和撤销

- 文献、笔记、批注使用 deletedAt 软删除，侧栏新增回收站；普通删除后的提示提供 10 秒撤销。回收站长期保留到用户手动清理。
- 文献移入回收站时暂停运行任务，保留 PDF、提取页面、批注和 AI 结果；恢复文献后可继续未完成任务。
- 独立笔记保留关联，点击已删除文献会提示先恢复；彻底删除文献才解除笔记关联。
- 先单独删除的批注不会因为恢复文献而自动复活，仍可在回收站单独恢复。批注恢复要求父文献存在且已恢复。
- 彻底删除与清空回收站均再次确认，永久删除文献时清理关联文件、页面、批注和任务，独立笔记保留。已移入回收站的笔记若被单独彻底删除，其草稿也清除。
- 再次导入回收站里相同的 PDF 会提示恢复或先彻底删除，避免隐形重复和浪费空间。

## 4. 笔记写入失败保护

每份笔记串行写入，以修订号保留最新内容。写入失败后状态显示「保存失败」，提供原因、重试、草稿导出和明确的放弃入口，不再一直显示「正在保存」。

每次编辑先写独立的本机草稿缓存，正式写入成功后清理；重启打开对应笔记会提示恢复草稿。若 IndexedDB 与 localStorage 都无法写入，只能在内存保留，界面明确提示关闭前导出。草稿不等同于正式笔记，完整资料库备份和恢复前会要求先处理已发现的未保存草稿。

离开笔记、切换笔记、搜索、打开文献和导入内容前检查未保存状态；正常的在途保存会先等待。失败时可返回、重试或保留草稿再离开。浏览器 beforeunload 与 Windows 原生窗口关闭监听分别保护关闭场景。

## 5. 单实例与任务恢复

桌面首先注册 [Tauri single-instance 插件](https://v2.tauri.app/plugin/single-instance/)，重复启动时恢复并聚焦原窗口。插件只在桌面目标编译。

前端以 Web Locks 保证同一资料库只有一个活动窗口；第二窗口显示占用提示，不初始化任务。只有获得锁的新窗口才恢复意外中断的任务。关闭原窗口后，第二窗口点击「重新打开」可接管。任务不会因重复打开窗口被误标记为取消。回收站文献也不能创建任务或写入延迟到达的结果。

## 6. 搜索与筛选

结果标题计数按关键词、标签和阅读状态共同计算。重置筛选同时清空搜索关键词。回收站内容不计入活动文献数、笔记数、批注数或任务列表。

## 升级与备份

关闭旧程序再安装 0.1.3。应用标识与资料库名称保持不变，schema 2 增加可选字段，不清空旧资料。完整备份输出格式 2，保留回收站；旧版格式 1 仍可导入。0.1.2 及更早的应用不能读取格式 2 备份。
